# ProOrgazm

Сайт салона (React + Vite) с бэкендом (Express + SQLite) и админ-панелью.

## Запуск

```bash
npm install
npm run dev        # сайт http://localhost:5173 + API http://localhost:3001
```

Продакшен — сервер сам отдаёт собранный фронтенд:

```bash
npm start   # http://localhost:3001
```

## Админка

`/admin`, логин **admin**. Пароль в репозитории не хранится — в `server/auth.js` лежит только его хеш (scrypt).
Сменить пароль:

```bash
node scripts/hash-password.mjs 'новый-пароль'
```

и подставить результат в `server/auth.js` (или задать на сервере переменной `ADMIN_PASS_HASH`). После смены пароля все старые
входы в админку сбрасываются.

- Дашборд: посетители, просмотры, клики «Записаться» (DIKIDI), конверсия, мессенджеры, источники, устройства
- Заявки из формы на странице контактов, со статусами
- Модерация отзывов (новые отзывы с сайта появляются только после одобрения)
- Массажи, мастера, статьи: редактирование, фото, порядок, скрытие с сайта
- Настройки: тексты главного экрана, контакты, ссылки DIKIDI, SEO

## Устройство

- `server/` — API. База `server/data/proorgazm.db` создаётся при первом запуске
  и заполняется из `src/data/site.js` (вместе с демо-статистикой за 30 дней — её можно очистить на дашборде).
  Загруженные фото лежат в `server/uploads/`.
- `src/` — сайт; контент приходит из `/api/content`, при недоступном API используется встроенный `src/data/site.js`.
- `src/admin/` — админка, грузится отдельным чанком.

Переменные окружения: `API_PORT` (3001), `ADMIN_USER`, `ADMIN_PASS_HASH` (или `ADMIN_PASS` открытым текстом), `DB_PATH`, `CORS_ORIGIN`.

## Деплой

### Боевой сайт: pro-orgazm.ru на хостинге Таймвеб (PHP)

На обычном хостинге Таймвеба нет Node.js, поэтому там работает PHP-версия API из папки `php/`
(те же адреса `/api/...`, та же база SQLite). Обновить сайт:

```bash
scripts/deploy-timeweb.sh
```

Скрипт собирает фронтенд, добавляет PHP-API и заливает всё по SSH в `~/pro-orgazm.ru/public_html`.
Фото из админки (`public_html/uploads`), база (`~/pro-orgazm.ru/data/proorgazm.db`) и настройки
(`~/pro-orgazm.ru/config.php`: логин и хеш пароля) при обновлении не трогаются, в репозиторий не попадают.
Сменить пароль админки — заменить `admin_pass_hash` в `config.php` на вывод
`php -r 'echo password_hash("новый-пароль", PASSWORD_DEFAULT);'`. Образец — `php/config.example.php`.

Сайт работает по https (сертификат Let's Encrypt в панели Таймвеба): `.htaccess` переводит http и www на https://pro-orgazm.ru.

### Вариант 1 — всё на одном Node-хостинге (проще всего)

VPS, Railway, Timeweb Cloud и т.п.: `npm install && npm start`. Сайт, API и админка на одном домене,
настраивать ничего не нужно. Для SQLite нужен постоянный диск: на Railway подключите Volume и укажите
`DB_PATH=/data/proorgazm.db`. Загруженные фото лежат в `server/uploads`, эту папку тоже нужно хранить на постоянном диске.

### Вариант 2 — сайт на Surge, API отдельно

Surge отдаёт только статические файлы, поэтому API разворачивается на Node-хостинге:

```bash
# на сервере API
API_PORT=3001 CORS_ORIGIN=https://ваш-домен.surge.sh npm run server
```

Сборка и деплой сайта с адресом API:

```bash
VITE_API_URL=https://api.ваш-домен.ru npm run build
npx surge dist ваш-домен.surge.sh
```

`200.html` создаётся при сборке автоматически: прямые ссылки на страницы на Surge открываются без 404.
Без `VITE_API_URL` сайт на Surge работает на встроенном контенте, а админка показывает, что сервер не подключён.

## Фото

Исходники лежат в `assets/originals` (`masters/`, `atmosphere/`, `logo.png`). Команда

```bash
npm run images
```

кадрирует их под пропорции блоков (4:5, 1:1) и сжимает в WebP 640 и 1200 px в `public/images`;
сайт сам выбирает размер под экран (`srcset`). Фото, загруженные через админку, сервер сжимает
автоматически (WebP 1600 и 640 px).

## Адреса страниц

`/massages`, `/masters`, `/reviews`, `/contacts`, `/blog`, `/privacy`. Старые адреса (`/massazhi`, `/stati/post/...`,
`/sergej-bog` и т.д., включая адреса proorgazm.ru) переадресуются на новые: сервер отвечает 301, на статическом хостинге
переадресует сам сайт. Таблица соответствий — `src/lib/routes.js`.

## Статьи

Статьи перенесены с proorgazm.ru командой `npm run import:articles`: текст — в `public/content/articles/*.json`,
список — в `src/data/articles.js`, обложки — в `public/images/blog` (WebP). Повторный запуск обновит файлы;
в базу новые статьи попадают при первом запуске сервера (старые шаблонные заменяются, свои статьи из админки не трогаются).
Английские адреса статей задаются в `src/lib/routes.js`.
